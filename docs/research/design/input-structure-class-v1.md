## 3. 투영: 탈출 관련 entry 집합 E (정적·어휘적)
entry 위치 i의 집합이고, 아래 규칙을 고정점까지 적용해 만든다. 재실행·oracle 내부를 쓰지 않는다.
1. **경로 탈출**: `abs(e.path)` 또는 `reach(0, N(e.path)) > 0`.
2. **대상 탈출**: 링크 entry이고 `abs(e.link_target)` 또는 `reach(0, N(e.link_target)) > 0` 또는 (symlink일 때) `reach(len(dirN(e.path)), N(e.link_target)) > 0`.
3. **E의 symlink 통과**(O-1형): e_s ∈ E가 symlink이고 s < i이며, `N(e_s.path)`가 `N(e_i.path)`의 진부분 접두.
4. **E로 이어지는 symlink 사슬**: e가 symlink이고 그 어휘적 해석 `res(e)`(초안 1 §5)가 E에 있는 symlink의 `N(path)`와 같다.
5. **E 객체를 가리키는 하드링크**: e가 hardlink이고 `N(e.link_target)`이 E에 있는 entry의 `N(path)`와 같다.
- 결정 사항(W4): 규칙 2에 절대 경로 대상(`abs`)을 넣었다. W4 문구("reach > 0")에는 없지만, 절대 대상은 어떤 기준으로 해석해도 추출 루트 밖이다. 빼려면 W4가 표시한다.
- E 밖의 entry는 분류에 들어가지 않는다. 같은 탈출 구조에 무관한 entry가 더해져도 E와 값은 같다.

# 정의 인용 (초안 2가 참조로 들인 초안 1의 절, 글자 그대로; 초안 1 sha256 `06e697cb4e7dcbed…`)

## 2. 정의
- 함수: `classify(case: ArchiveCase) -> InputStructureClass`.
  - 인자는 논리 입력 하나(entry 열 `e_0 … e_{n-1}`, 각 entry = path, entry_type, content, link_target, mode)뿐이다.
  - 추출 결과·관찰·판정·대상·설정을 받지 않는다.
  - 순수 함수다: 같은 입력에 같은 값을 내고, 부작용·난수·시계·환경 의존이 없다.
  - 유효한 모든 `ArchiveCase`에서 정의된다(예외 없음). 빈 case도 포함한다.
- 출력: 아래 축들의 값을 담은 레코드. 정준 JSON(키 정렬, 공백 없음, ASCII)과 `class_id = sha256(정준 JSON)` 앞 16 hex.
- 기록 위치(v2 엔진): step 레코드의 `input_structure`(값 레코드 + `classifier` = 이 id). build-invalid step 포함, 모든 step에 남긴다.

### 2.1 경로 정규화 N (분류 전용)
- 문자열 s에 대해 `abs(s)` = s가 `/`로 시작하는가.
- `N(s)` = s를 `/`로 나눈 조각 열에서 빈 조각과 `.`을 지운 것. `..`는 남긴다. 다른 정규화(대소문자, 유니코드, 끝 구분자 의미)는 하지 않는다.
- 이 정규화는 분류에만 쓴다. 빌더·변이·oracle·추출기 동작과 관계없다.
- 깊이 걸음 `walk(start, comps)`: 값 d = start에서 시작해, 조각이 `..`면 d−1, 아니면 d+1. **최저값** m.
  `reach(start, comps) = max(0, −m)` = 시작점보다 몇 단계 위로 올라갔는가(어휘적으로).
- 이름 조각: `..`가 아닌 N의 원소. 이름 조각의 **글자**는 같음/다름 비교에만 쓰고 값에 넣지 않는다.
- `dirN(p)` = `N(p)`의 마지막 원소를 뺀 열(부모 조각들).
- `B(k)` = 구간 표기: 0, 1, 2, 3, `4+`(정수 k ≥ 4).

## 5. 축 3 — symlink 사슬 길이
- 어휘적 해석 `res(e)`(symlink e의 대상):
  - absolute면 `N(target)`.
  - 아니면 `dirN(path) + N(target)`을 걸어 `..`를 앞 조각과 지운 열이다. 걷다가 0 아래로 내려가면(루트 밖) `None`.
- 간선 e → f: f가 symlink이고 `res(e) == N(f.path)`. 위치·순서와 무관하게 entry 전체에서 본다.
- 값: `chain = C3(최장 경로의 symlink 수)` ∈ {0, 1, 2, `3+`}. symlink가 없으면 0, 간선 없는 symlink만 있으면 1.
- 순환이 있으면 `cycle = true`(별도 불리언)이고, `chain`은 순환을 한 번 돈 길이까지만 센다.
- 근거: freeze-2 §2.1 L2 사슬 k단.

## 6. 축 4 — 순서 패턴 5종 (명시 목록, 각 불리언)
모두 entry 열의 **위치 i < j**와 N 비교로만 정한다. 이름의 글자는 같음 비교에만 쓴다.

| # | 이름 | 정의 | 일반 구조 예 |
|---|---|---|---|
| O-1 | `pass_through_prior_symlink` | i < j, e_i가 symlink, `N(e_i.path)`가 `N(e_j.path)`의 **진부분 접두**(조각 단위) | `[symlink d → t, regular d/f]` |
| O-2 | `duplicate_path` | i < j, `N(e_i.path) == N(e_j.path)`(종류 무관) | `[regular a, regular a]` |
| O-3 | `child_before_parent` | i < j, e_j가 directory, `N(e_j.path)`가 `N(e_i.path)`의 진부분 접두 | `[regular p/f, directory p]` |
| O-4 | `same_path_type_change` | i < j, `N(e_i.path) == N(e_j.path)`, `e_i.entry_type ≠ e_j.entry_type`. 불리언과 함께, 나온 **(앞 종류, 뒤 종류) 순서쌍의 집합**을 기록 | `[directory a, symlink a → t]` → {(directory, symlink)} |
| O-5 | `hardlink_forward_reference` | e_i가 hardlink이고, `N(e_i.link_target)`(absolute면 그대로, relative면 그대로, 기준 해석 없음)과 같은 `N(path)`를 가진 entry가 **j > i에만** 있고 k < i에는 없다 | `[hardlink h → b, regular b]` |

- O-2와 O-4는 겹칠 수 있다(O-4는 O-2의 부분집합). 둘 다 기록한다.
- 근거: freeze-2 §2(O1 순서 의존 `:162-165`, L2 타입 교체 `:160-161`), §2.1(`:184-186`).

## 7. 불변 조건과 테스트 (구현 동결 조건)
1. **순수성·의존**: 구현 모듈은 `inodefence.model.archive`만 import한다. `oracle`, `feedback`, `mutator`, `observer`, `targets`, `evaluation`은 이 모듈을 import하지 않는다. 두 방향 import 그래프 테스트로 확인한다.
2. **이름 바꾸기 불변**: `..`·`.`·빈 조각이 아닌 이름 조각에 단사 이름 바꾸기 σ를 path와 link_target 전체에 일관되게 적용해도 `classify` 값이 같다.
   속성 테스트: 무작위 case × 무작위 σ. 이름 바꾸기 대상에는 `outside`, `sentinel` 같은 하네스 토큰도 포함한다.
3. **결정성**: `PYTHONHASHSEED`를 바꿔도 같은 값(집합은 정렬해 직렬화).
4. **arm 무관**: 함수에 arm·정책 인자가 없다. 세 arm 합성 실행에서 같은 case_id는 같은 `class_id`다.
5. **판정과 분리**: 계약은 기록하지 않는다. `classify`는 실행 전·빌드 전 값만 본다. build-invalid case도 분류된다.
6. **content·mode 비의존**: content 바이트와 mode를 바꿔도 값이 같다(이 판에서는 축이 아님, §8).
7. **값 영역 유한**: 축 1 = 3⁴, 축 2 = 링크 튜플 공간(2×2×5×5×5 = 500)의 부분집합, 축 3 = 4×2, 축 4 = 2⁵ × (4×3 순서쌍)의 부분집합.

  - W3 `depth_bfs` **dry-run witness**(cap 3, W3의 축소 매개변수 격자). **공식 d* witness는 아직 아니다.** 나오면 다시 확인한다.
- **발견: #509 계열 술어끼리 겹친다** (자료는 저장소 밖 보정 자료)
  - 탈출 대상 typeswap 손 입력은 L2-typeswap과 O1-order를 **둘 다** 만족한다.
  - O1-order·L2-chain의 BFS witness도 L2-typeswap을 만족한다.
  - L2-typeswap**만** 만족하는 입력은 symlink 대상이 탈출하지 않는 경우뿐이다(손 입력 1, BFS witness 1).
  - 그래서 쌍별 구분은 **술어 하나만 만족하는 입력**으로 판정한다. 두 계열에 동시에 속한 입력은 어느 분류기로도 "다른 분류"에 둘 수 없다.

| L4 분류(현 정의, 사다리 L4) | L1-escape | L1-escape-sym | L1-cwd | L2-chain | L2-typeswap만 | O1-order만 |
|---|---|---|---|---|---|---|
| 분류 | target·hardlink·reach{0(절대),1+} | target·symlink·reach1+, 사슬1 | `none` | target·symlink, 사슬 2, O-1 | `none` | target·symlink, 사슬 1, O-1 |
- 쌍별 결과(술어 하나만 만족하는 입력, L0–L4 모두 같음):
  - **구분됨**: L1-escape | L1-escape-sym(종류·사슬), L1-escape | 나머지 전부, L2-chain | O1-order(사슬 2 대 1), L2-chain | L1-cwd·typeswap만, O1-order | L1-cwd·typeswap만, L1-escape-sym | O1-order(O-1).
  - **구분 안 됨**: L1-cwd | L2-typeswap만. **둘 다 어휘적 탈출이 아니라 `none`**이다(링크 대상 기준을 설계상 뺀 결과, §11.4 한계). 더 잔 사다리 단계(L0까지)에서도 같다.
  - 두 계열에 걸친 입력(typeswap ∩ O1): O1-order만과 같은 분류. 투영 규칙 1–5가 같은 이름의 앞 entry(디렉터리)를 E에 넣지 않아 O-4가 켜지지 않기 때문이다.
- 판정(W4 원칙에 대입): **현 L4는 술어 하나에만 속하는 모든 계열 쌍을 가른다. 단 "어휘적 탈출이 아닌" 두 계열(L1-cwd, typeswap만)은 함께 `none`이다.** 이것은 사다리 단계를 바꿔도 풀리지 않는 정의상 한계라서 사다리 규칙("더 잔 단계로")은 적용되지 않는다. W4 확인 사항이다.
- **진단(채택 안 함)**: 후보 규칙 6 "E에 있는 entry와 정규화 경로가 같은 entry는 E에 들어간다"(일반·어휘적).
  - 결과 (자료는 저장소 밖 보정 자료)
  - 기준 줄 L4 중앙값은 42 → **50**(합친 66 → 81, 최빈 0.47 → 0.27).
  - 이 규칙은 사다리 밖 정의 추가라서 W4가 고를 일이다. 술어 하나만 만족하는 입력의 구분에는 필요 없다.

- **W3 손 witness로 재확인** (자료는 저장소 밖 보정 자료)
  - 결과는 같다. L1-escape·L1-cwd·L2-chain·O1-order의 W3 witness는 술어 하나에만 속하고 L4에서 서로 다른 분류다(L1-cwd만 `none`).
  - W3의 L2-typeswap witness는 O1-order도 만족하고(W3가 직접 밝힘), O1-order와 같은 분류다.
  - W3: typeswap은 seed s1에서 깊이 1일 가능성이 커 깊이 ≥ 2 창에서 빠질 수 있다. 최종 계열 집합은 공식 d*가 정한다.
  - 최종 집합에 typeswap이 남으면 typeswap 대 O1 구분은 계열 정의(W3)나 규칙 6(W4) 중 하나로 정한다.

### 11.5 이후 계획 (W4 승인 (b))
- freeze-3이 v2 엔진에 구현된 뒤, 실제 엔진으로 §11.1 표와 §11.3 확인을 다시 계산해 부록으로 덧붙인다. 동결 정의는 바꾸지 않는 일관성 확인이고, 차이는 W4에 보고한다.
- W3의 공식 d* witness가 나오면 §11.3을 그 witness로 다시 확인한다.

## 부록 추가: 서명 뒤 확인 (2026-11-18, 정의 불변)
- W3가 #509 계열 술어를 서로소로 고쳤다(W4 판정):
  - L2-typeswap = 같은 경로의 앞선 다른 종류 entry를 대체한 symlink + 탈출 + 통과.
  - O1-order = 그런 앞선 entry가 없는 단일 symlink + 탈출 + 통과.
  - L2-chain = 사슬 k ≥ 2.
- 새 술어로 다시 확인했다. 손 입력과 W3 손 witness가 모두 술어 하나에만 속한다.
- 술어에 속하는 입력만으로 본 L4 쌍별 결과:
  - **L2-typeswap | O1-order만 같은 분류다.** 투영이 같은 이름의 앞 entry를 E에 넣지 않아 O-4가 켜지지 않기 때문이다. 이는 위 "사전 고지된 조건"이 다루는 경우이고, 두 계열이 모두 채택되면 freeze-2(규칙 6)로 재발행한다.
  - 나머지 모든 쌍은 구분된다.
  - 새 술어에서는 typeswap이 탈출을 요구하므로, 앞서 적은 L1-cwd 대 typeswap-only의 `none` 충돌은 술어에 속하는 입력 사이에서는 더 나타나지 않는다. L1-cwd는 여전히 `none`이다(§11.4).
- 공식 d* witness가 나오면 같은 확인을 다시 한다.
