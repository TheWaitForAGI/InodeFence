# 호스트별 적격성 검증 v1 — 본실험 선행 조건 (비등록, `demo run`)

> **비등록·비합산 인프라 점검.** 라벨은 `demo run`이다. 가설 검정이 아니고 EXP-0·파일럿·벤치마크·EXP-3·EXP-2 데이터에 합치지 않는다. oracle은 봉인한다(§3 봉인). 판정 대상은 **그 호스트가 그 실행 SHA·이미지·Engine에서 jobs=2로 본실험 런처를 돌릴 인프라 자격이 있는가**뿐이다.
>
> **상태:** 측정 전 설계 초안(2026-11-11). 결정 기록은 [D047](../../docs/DECISIONS.md#d047--본실험-선행-조건-단순화-jobs2-고정과-호스트별-적격성-검증-초안)이다. 실행하지 않았다. **W4 독립 검토(표본 구성과 통과 기준, §15)와 지웅 승인 전에는 실행하지 않는다.** "잠정" 표시 값은 W4 검토 뒤 측정 전에 확정하며, 확정 뒤에는 결과를 보고 바꾸지 않는다. 이 파일이 머지된 커밋에서 동결하고, 동결 뒤 변경은 새 버전 파일로만 한다.
>
> **대체 관계.** [동시 실행 벤치마크 v3](concurrency-scaling-v3.md)는 D047로 본실험 선행 조건에서 빠졌다(문서와 도구는 보존). v3 정정 초안(#337 `fd08c3a`)의 §5.1 run_exp0 엔지니어링 smoke, §8 점검표 보강, Engine B안 문단 가운데 본실험 경로에 해당하는 내용을 이 파일로 옮겼다. probe(seed 6200–6207)와 V7′·X1 판정은 옮기지 않았다.
>
> 과거 Stage A(68af9b4)와 파일럿의 oracle 값은 이 설계를 쓰는 동안 보지 않았다. 임계는 과거 결과를 보고 다시 정하지 않았다.

## 1. 목적과 주장 범위

- **목적:** 본실험(EXP-3 train, EXP-2 holdout)에 참여할 호스트를 미리 고정한 기준으로 정한다. 본실험 oracle 값이 하나도 없을 때 정한다.
- **주장하는 것:** 통과는 "그 호스트가 그 실행 SHA·이미지·Engine·jobs=2에서 12캠페인 동안 정해진 인프라 기준을 지켰다"는 사실뿐이다.
- **주장하지 않는 것:**
  - 장기 안정성의 통계적 증명이 아니다. 12캠페인에서 abort 0이어도 캠페인당 abort율의 95% 상한은 약 .22다(1 − .05^(1/12), 계산).
  - H1의 공식 결과가 아니다.
  - EXP-3 abort율의 추정값이 아니다. 측정 seed는 파일럿 abort 이력으로 골랐다(D041). 그래서 이 abort 비율을 EXP-3의 n·abort 추정에 쓰지 않는다.
  - 동시 실행 수 선정이 아니다. jobs=2는 사람 결정이다(D047).
- **D040-D21 재측정과의 관계(W4 의견으로 확인):** D046이 남긴 "jobs 2·j* 각 1블록 재측정"은 j* = 2이므로 jobs 2 블록 1개다. 이 검증의 12셀(측정 seed 4개 × 3 arm, budget 2000)은 v2 블록 12셀과 구성이 같으므로 그 요구를 충족하는 것으로 본다. 실행기와 런처 재시도가 다르다는 점은 §16에 적는다.

**seed 6300–6303의 근거.** 원장, v1·v2·v3, `RESERVED_SEED_RANGES`, v3 probe 6200–6207(미실행), v1 6100–6103, D042 정지·재개 smoke 6101–6104와 겹치지 않는다. main의 configs·preregistration·DECISIONS에 6300–6399 사용처가 없다(2026-11-11 v3 정정 초안의 확인을 옮김, 이 PR에서 다시 확인하지 않았다).

**봉인.** 어떤 세션도 이 실행 raw의 oracle 필드(C0/C1/C2 값, hit, T_first, U_viol)를 읽지 않는다. 판정 도구(§13)는 oracle이 아닌 필드만 읽고, 교차 호스트 비교는 메모리 안에서 해시 일치만 보며 값을 내보내지 않는다(v2 §6.6과 같은 방식). 이 실행은 n, k, arm, EXP-2 GO의 입력이 아니다.

**원장.** 실행 전에 LOG에 계획 1줄(호스트, seed, budget, jobs, 봉인)을 남긴다. 실행 뒤, EXP-3의 `exposure_ledger_sha256` 동결 전에 호스트별 행을 7.5.2에 추가한다: exposure_kind "비등록 호스트 적격성 검증 (`demo run`, oracle 봉인·미열람, 파일럿 재실행)", seed, budget, jobs, 셀 수, 결정론 재실행 횟수, 실행 SHA, 이미지, 매니페스트 sha.

**실행 등록 파일(W3 작성, 비등록 라벨).** 사전등록 형식을 쓰되 `experiments/preregistration/` 밖에 둔다(예: `experiments/configs/host-qualification-v1-run.md`). exp3-v1과 다른 값은 `experiment_id`(예: `host-qual`), `seeds = 8110, 8102, 8103, 8106`, `execution_deadline`, `seed_assignment_rule = replicate-v1`과 그 `seed_assignment_sha256`뿐이어야 한다. budget 2000, arm, 대상, sentinel, watchdog, `jobs_max = 2`, `host.<id>.jobs = 2`는 exp3-v1과 같다.

## 4. preflight (호스트별, 시작 전 모두 충족; 하나라도 어긋나면 시작하지 않는다)

- 실행 SHA가 clean이고 기록한 후보 SHA와 같다(깨끗한 detached worktree, venv python, `uv.lock` 생성 없음).
- 대상·controller·helper local 이미지 id가 기대값과 같다: 대상 `sha256:22c8734f141d91b333ba37c7fe6a9a7547d7abfab487fa028da2053bed6f3dbb`, controller `sha256:d44900e13ed5083db54cefda8833328d4da61148f62213d86f07afa78191d7a4`, helper `sha256:9b9dd606c49ff0051465fe9e435351f33623d949f360d6518580855e3781cc27`. 본실험 런처가 세 id를 시작과 끝에 기록하고, 판정(§5 Q6)이 기대 id와 대조한다. 지금 런처는 controller·helper local 이미지의 **존재만** 확인한다(방법론 담당 지적). 세 id 기록·대조는 측정 전에 들어가야 하는 코드 항목이다(§13). HOST2는 `docker save`/`load`로 옮긴 경우 id 보존을 확인한다.
- Dockerfile은 해시 대상이 아니다. 셀은 빌드를 건너뛰고(`SKIP_BUILD=1`) 이미지 id가 고정되어 있으므로, 실행을 정하는 것은 Dockerfile이 아니라 이미지 id다.
- Docker Engine(Server.Version)이 그 호스트의 기록값과 같다: HOST1 29.8.0, HOST2 29.9.3. `docker context show`와 소켓을 서빙하는 daemon을 기록한다.
- 공유 실행 경로 해시: #336 `b7baf3a`의 `SHARED_PATH_FILES` **16개 파일**(`scripts/launcher_guards.py`, `host_preflight`가 하나라도 없으면 거부)의 sha256을 기록한다. 두 호스트에서 같아야 한다. 이 목록에는 보호 파일도 들어 있으나 읽고 해시만 낸다.
- 실행 중 컨테이너 0, 잔존 리소스 0(`inodefence-` 접두 컨테이너·볼륨).
- 디스크·메모리·부하: v2 §7과 같다(디스크 여유 20 GB 이상, 가용 메모리 15 GiB 이상, load < 3, 그리고 v2 §5의 load < 코어의 25%).
- 호스트 재시작 보호 설정의 캡처, 부팅 시각, Docker Desktop·WSL 버전, `.wslconfig` 값(메모리·프로세서 상한), 실시간 동기 상태(`adjtimex` 또는 `timedatectl`)를 기록한다. 부팅 시각과 버전은 끝에 다시 기록해 같음을 확인한다.
  - HOST2 시계: WSL의 timesyncd는 꺼 둔 상태로 유지하고, Windows 시간 서비스(W32Time)를 NTP에 동기화하는 방식을 지웅이 승인했다. 적용은 확인 시험 뒤이며, 결과는 미정이다.
- 호스트 간 realtime 시계 차를 기록한다(v3 정정 초안 §8 보강 6항목 가운데 옮기지 않았던 1건). 판정 입력이 아니라 기록만이다. HOST2가 불참이면 "해당 없음"이다.
  - **측정 시점:** 적격성 시작과 끝, 동결 시점, GO 시점.
  - **기본(2차 방법): SNTP 오프셋 차.** 각 호스트의 WSL 안에서 같은 NTP 서버에 5회 질의해 지연이 가장 짧은 표본을 쓴다. 차 = offset_H2 − offset_H1, 불확실성 = 두 쪽 RTT/2의 합. 서버 이름을 기록한다.
  - **1차 방법(SSH 셸 접근이 따로 승인된 경우만): Tailscale SSH 왕복 괄호 측정.** HOST1에서 t0 = CLOCK_REALTIME, ssh로 HOST2의 CLOCK_REALTIME t2, t1 = CLOCK_REALTIME을 잰다. 차 = t2 − (t0+t1)/2, 불확실성 ±(t1−t0)/2. 5회 중 왕복이 가장 짧은 표본을 쓰고 5회 모두 기록한다. 두 호스트 모두 WSL 안의 CLOCK_REALTIME(기록 파일이 쓰는 시계)이다. 현재 HOST1→HOST2 방향 SSH는 열려 있지 않다(전송용 HOST2→HOST1 읽기 전용 rrsync 키만 있고 셸은 막혀 있음). 그래서 이 방법이 가능한지는 미확인이다.
  - **출력:** `--clock-reference`에 {method, samples, chosen, diff_s, uncertainty_s, measured_at}.

**Q8 적용 범위.** Q8은 최종 상태가 abort-final인 셀에만 적용한다. 첫 시도가 무기록이고 재시도가 성공한 셀은 Q7(첫 시도 기준 abort 비율)의 분자에는 들어가지만 Q8 대상이 아니다. 그 첫 시도의 `attempts/` 로그에 있는 `FAILED at step` 줄과 첫 오류는 "재시도로 복구된 첫 시도 실패" 목록으로 보고만 한다(게이트 아님).

**입력 종속 검사(통과가 아니라 정지).** abort가 HOST1 Stage A jobs=2 abort와 같은 (arm, seed, step index, case id)에서 다시 나면 입력 종속으로 보고 그 호스트의 실행을 멈춘다(v2 §6.5의 재발 규칙). 보고하고, 적격 판정을 내지 않는다. 정지 규칙의 범위는 **Stage A jobs=2만**이다. Stage A 쪽 입력은 `~/inodefence-benchmarks/concurrency-scaling-v2/A/`의 jobs=2 블록 abort 스텁(`step_index`, case id)만이다. 경로가 Stage A와 갈라진 셀은 이 검사가 시험하지 못한 것이며, "시험 안 됨" 수를 적는다. **전제:** 적격성 셀 env와 Stage A 셀 env가 같아야 한다(§12 점검표). 다르면 이 검사는 무효이며, 그 사실을 실행 전에 기록한다.

**파일럿 abort 6조합 대조(보고만).** 파일럿에서 abort한 6조합(8110의 세 arm, S-u 8102, R-restart 8103, D 8106)에 대해 case_id만 읽어 같은 위치를 지났는지·같은 위치에서 abort했는지를 보고한다. v2 §6.5의 파일럿 대조와 같은 성격이며 정지 규칙이 아니다.

**보고만 하는 값(게이트 아님).** Docker 호출 timeout 수(출처는 §2와 같다), 셀별 인프라 재실행 수, 런처 재시도 수, 처리량(exec/h, 실시간), StartGate 대기 분포, 호스트별 mono/real 시계 배율. 재실행이 있었던 셀은 §2의 결정론 검사를 같은 방식으로 한다(D046 UNKNOWN "재실행 결과가 원 실행과 같다는 전제"의 실 docker 확인).

## 7. 교차 호스트 공통 seed 비교 (X1 선정 게이트를 대체; 지웅 결정 2 반영)

- **시점:** 두 호스트의 적격성 실행이 모두 끝난 뒤 1회.
- **방법:** 같은 (arm, seed)에 대해 HOST1과 HOST2의 step별 경로를 공통 앞부분까지 비교한다. 비교 항목은 `case_id` 순서, `trace_termination`, step별 판정값(oracle + feedback 키)의 해시다. abort 셀은 abort 시점까지 비교한다. 비교기는 해시 일치만 보고 값은 내보내지 않는다(oracle-blind).
- **도구:** `scripts/compare_pilot_rerun_paths.py`는 **그대로 쓸 수 없다.** 입력이 벤치마크 `block.json`과 파일럿 설계이고, 비교 대상이 `case_id`뿐이며 판정값 해시를 보지 않는다(코드 읽기, main `dfccedc`). 재사용 후보는 `scripts/analyze_concurrency_benchmark.py`의 `cell_path`·`compare_paths`(V9와 같은 방식: case_id·trace_termination·oracle+feedback 해시, 공통 앞부분)이며, run_exp0 출력 배치를 읽는 얇은 비교기가 필요하다(W3, §13).
- **보고:** 불일치 셀 수 m_x, 비교 불가 셀 수(어느 한쪽의 기록이 없거나 읽을 수 없음), 첫 불일치 step이 한쪽에서만 `timed_out`·`failed`인 셀 수, 재실행이 있었던 셀의 불일치(따로 표시).
**지웅 결정 2(2026-11-11, 원문 인용 일부):** "공통 seed 비교에서 설명되지 않는 중대한 불일치가 발견되면 해당 호스트 투입을 보류하고 원인을 보고한다." 아래 1~4는 ORCH 구체화이며 W4 검증 대상이다. 측정 전에 고정한다.

1. **보고만:** m_x ≤ 1이고 비교 불가 ≤ 1이면 결과를 보고만 한다.
2. **설명 필요:** m_x ≥ 2 또는 비교 불가 ≥ 2이면 "설명 필요" 상태다. 설명 절차는 다음과 같다. 불일치 셀마다 두 호스트 각각에서 같은 셀을 1회 재실행한다(같은 설정, 별도 출력, 비등록 `demo run`, oracle 봉인, 원장 기재, 같은 seed라 새 노출 아님). 각 호스트의 재실행을 **그 호스트 자신의** 원 실행과 경로 해시로 비교한다.
   - 어느 한 호스트라도 자기 재실행이 자기 원 실행과 다르면, 그 셀의 불일치는 "호스트와 무관한 비결정성으로 설명됨"이다.
   - 두 호스트 모두 자기 재실행과는 일치하는데 호스트 사이에만 다르면 "설명되지 않는 호스트 종속 불일치"다.
   - 비용: 재실행은 셀당 약 25~50분(추정)이고 두 호스트에서 각각 돈다.
   - 보고(보류 사유 아님): 비교기는 셀마다 어느 호스트의 자기 불일치로 설명됐는지를 적는다. "HOST2 단독 비결정성"(HOST2만 자기 재실행과 다르고 HOST1은 자기와 일치) 셀 수와 "HOST1 단독 비결정성" 셀 수를 따로 낸다. 이 셀들은 지웅 원문의 "설명되지 않는"에 들지 않으므로 보류 사유가 아니고, 보고·해석 주의 대상이다.
3. **중대한 불일치 = 설명되지 않는 호스트 종속 불일치가 2셀 이상.** 이때 기준 호스트(HOST1: 승인된 실행 기준 Engine 29.8.0, EXP-0 실행 호스트)가 아닌 호스트(HOST2)의 투입을 보류하고 원인을 보고한다. 보류 해제는 원인이 기록되고 지웅이 승인한 경우에만, 동결 전에 한다. 동결 시점에 보류 상태면 그 호스트는 참여 집합에 들어가지 않는다.
4. **운영특성(사실대로, R4 유지).** 같은 호스트 안의 반복이 없어 바닥값 F를 잴 수 없으므로, 비교 결과만으로는 동시 실행·관찰의 비결정성과 호스트 종속을 **구분하지 못한다.** 비결정성만으로도 셀당 쌍 불일치율 q가 .05면 m_x ≥ 2일 확률이 .118, q가 .10이면 .341이다(정확 계산, 12셀, 셀 독립 가정). 즉 "설명 필요" 상태는 그만큼 자주 생길 수 있다. 2의 재실행 절차는 단순 비결정 모형(실행마다 독립적으로 이탈하고, 이탈한 경로끼리는 일치하지 않음)에서는 둘을 가른다. 재실행이 1회라 계통적 비결정성이나 재현되는 이탈은 놓칠 수 있다.

- **보류가 "결과 관찰 뒤 호스트 제외 금지"와 충돌하지 않는 이유.** 보류는 본실험 시작 전에, oracle 값은 읽지 않고, 판정값(oracle + feedback 키)을 해시로만 비교한 일치 여부로 정한다. 비교 항목에 적격성 실행의 판정값 해시가 들어간다는 점은 숨기지 않는다. 본실험 결과(oracle 값)는 아직 없다. (이전 문구 "이 비교는 어떤 호스트도 제외하지 않는다"는 이 결정으로 대체했다.)
- **분석상의 귀결.** 호스트별 민감도 표는 이 비교와 무관하게 언제나 보고한다(exp3-v1 §6, exp2-v1 §5). 참여한 두 호스트 사이에 "설명 필요"였던 셀이 있으면, 그 표와 본 분석 결과 옆에 "호스트 사이 경로가 달랐으므로 합동 결과를 호스트 차이와 함께 읽어야 한다"는 해석 주의 문구를 붙인다. 분석 구조와 판정은 바꾸지 않는다.
- **비교 불가 셀(ORCH 결정 2026-11-11, 지웅 승인 = PR 머지, W4 검증 대상).** 비교 불가 셀은 한쪽 호스트에 그 셀의 경로 기록이 없는 셀이다(예: abort로 경로가 끝까지 없음). 이것은 호스트 종속 불일치의 증거가 아니다.
  - 기록이 없는 쪽 호스트에서 그 셀을 1회 재실행한다(같은 설정, 별도 출력, 비등록, 원장 기재). 비교 가능해지면 일반 절차로 넘긴다: 일치면 끝, 불일치면 2의 설명 절차.
  - 재실행 뒤에도 비교 불가로 남은 셀은 "비교 불가(미해소)"로 수를 보고한다. "중대한 불일치" 계산(설명되지 않는 호스트 종속 불일치 2셀 이상)에는 넣지 않는다.
  - 재실행 뒤에도 비교 가능 셀이 10개 미만이면 "교차 비교 미완"으로 보고한다. 이는 불일치의 증거가 아니라 증거 부족이므로 자동 보류 사유가 아니다. 동결 전에 지웅에게 보고해 그 호스트의 투입 여부를 결정받는다(결정 입력은 비교 가능 셀 수와 미해소 사유뿐). 자동 보류는 지웅 원문대로 "설명되지 않는 중대한 불일치(2셀 이상)"뿐이다. (2026-11-11 `541a933`의 "10개 미만이면 HOST2 투입 보류"는 지웅 원문보다 엄격해 삭제했다.)
  - 그 셀의 abort 자체는 각 호스트의 적격성 기준(Q7 등)이 이미 센다. 교차 비교에서 다시 세지 않는다.
- 한 호스트만 적격성을 마쳤으면 "교차 비교 없음(단일 호스트)"으로 적는다.

## 8. 실패, 재실행, 재적격

- **실패하면:** 멈추고, 원인을 조사해 기록한다. 통과시키려고 기준이나 seed를 바꾸지 않는다.
- **재실행:** 기록된 수정 또는 기록된 외부 원인 뒤에만 허용한다. 같은 기준·같은 seed로 한다. 모든 시도(실패 포함)를 원장과 LOG에 공개한다. 재실행도 단계 실행 승인을 다시 받는다.
- **재적격:** 통과 뒤 공유 실행 경로(§4의 16개 파일 해시)나 이미지 id 3개·Engine·Desktop·WSL 버전이 바뀌면 그 호스트는 smoke부터 다시 적격성을 받는다.

## 9. 호스트 참여 규칙과 HOST2 불참 시 규칙 (사전등록 전 명시)

**포함 규칙.** 호스트는 동결 시점에 (1) 자기 적격성이 이 파일의 사전 고정 기준으로 통과했고 (2) §7의 투입 보류 상태(설명되지 않는 중대한 불일치 2셀 이상)가 아닐 때만 본실험에 참여한다. "교차 비교 미완"(비교 가능 셀 10개 미만)은 보류 사유가 아니라 **지웅 결정 항목**이다. 동결 전에 지웅이 그 호스트의 투입 여부를 정하며, 투입하지 않기로 하면 참여 집합에 들어가지 않는다. 모두 본실험 oracle 값이 없을 때 정해진다. 처리량과 본실험 결과는 포함 여부에 쓰지 않는다. 본실험 결과를 본 뒤 호스트를 빼지 않는다.

**HOST1은 기다리지 않는다.** HOST1은 HOST2의 Tailscale 연결이나 재시작 보호를 기다리지 않고 smoke와 적격성을 진행한다. 각 단계 실행은 지웅 승인 게이트를 유지한다.

**참여 호스트 집합은 동결 시점에 한 번 고정한다(ORCH 결정 2026-11-11, 지웅 승인 = PR 머지).** 이유: D043의 r 정의를 바꾸지 않는다. 호스트 키를 동결 뒤에 등록할 필요가 없다. 호스트 전용 기간(11/18~26)에 적격성 실행을 돌릴 일이 없다. 단일 호스트로도 GO 최소가 추정상 실행 창 안에 들어간다(§10, abort·정지 무시 추정).

### 9.1 train 중 한 호스트가 정지하고 재개되지 않는 경우 (지웅 결정 1)

**지웅 원문(2026-11-11, (b) 조건부 승인).**

> - 가동 중인 호스트만으로 GO 판정을 산출할 수 있도록 허용한다.
> - 단, 사전등록된 최소 seed 수, 유효 표본 수, 품질 기준을 모두 충족해야 한다.
> - 호스트 중단이 연구 결과와 연관되었을 가능성이 있거나 증거 무결성에 의문이 있으면 GO를 보류한다.
> - 미완료 데이터, 중단 원인, 실제 완료 범위를 명시하고 전체 실험 완료로 표현하지 않는다.
> - EXP-2 진행 가능 여부와 전체 holdout 완료 여부는 구분한다.
> - 해당 변경은 train 결과 확인 전 설계 PR로 승인·동결해야 한다.

**ORCH 구체화(W4 검증 대상).** 이 결정은 D043 조건 6(미재개면 GO 미산출)을 개정한다(D047).

1. **적용 시점과 제외.** GO 판정 시각에 참여 호스트 가운데 마지막 인프라 사건이 미재개 `infrastructure-stop`인 호스트가 있을 때 적용한다. 그 호스트를 r과 holdout 할당에서 뺀다(r = 가동 중인 참여 호스트의 train r_h 합). (가) 제외된 호스트의 **완료된** train 셀은 E, train abort, e, train 탐색 결과에 그대로 남고 r에서만 빠진다. (나) 미완주 train seed는 GO 판정 시각에 끝나지 않은 seed 블록이며, D041 마감 규칙을 준용해 train 분석에서 빼고 그 수를 보고한다. (다) 제외된 호스트는 GO 뒤 train을 재개하지 않는다. 모든 참여 호스트가 미재개 정지면 GO는 미산출이다.
2. **"사전등록된 최소 seed 수·유효 표본 수·품질 기준" = 기존 등록 기준을 완화 없이 그대로(해석 (가), 기본값). 지웅 확인 대기.** 대안 (나)는 train 시작 전에 숫자를 지금 정하는 것이다(예: 가동 호스트의 완주 train seed 블록 수 하한). 지웅이 (나)의 값을 주면 이 항목에 더한다. 어느 쪽이든 완주 seed 블록 수는 보고한다(4).
   - 용량 ⌊H_rem·r ÷ (6000·e)⌋ ≥ 76(가동 호스트의 r로).
   - E ≥ 1(D040-D11 정의 그대로: train 첫 C1∨C2 캠페인 수, 3 arm 합산, abort 포함, invalid 제외).
   - train abort ≤ .45(D045 분모: 시도한 셀, **제외된 호스트의 시도 셀 포함**).
   - 가동 호스트의 train 기록 완전성(`cell_completeness`) pass.
   - **등록된 별도 최소 유효 표본 기준은 없다.** 확인 위치: `docs/DECISIONS.md` D040(D1·D7·D11·D12·D14, 운영 조건), D041(마감·abort 집계·운영 중단), D043, D045, #332 `ff13109`의 exp3-v1 §2·§4·§5와 exp2-v1 §2·§5. 가까운 값은 `event_threshold = 7`(D040-D14, exp2-v1:53·153)과 D12의 "I < 7 → 미검정" 행인데, 둘 다 holdout 확증 분석의 정보 블록 I에 대한 기각 가능성 플래그·판정표 행이며 GO 입력이 아니다. 새 임계는 만들지 않았다. 검증자가 판단한다.
3. **GO 보류 조건.** 하나라도 해당하면 GO를 내지 않고 지웅 판단으로 올린다. 판정 입력은 인프라 값과 기록 상태뿐이고 oracle 값은 쓰지 않는다.
   - (i) 정지 원인이 미확인(§5 Q8의 미확인 정의 준용)이거나, 인프라·외부 원인으로 분류되지 않는다.
   - (ii) 그 호스트의 train abort 전체가 입력 종속 패턴을 보인다: 같은 (arm, seed, step, case_id) 재발, 또는 그 호스트의 arm×abort 표에 대한 독립성 검정(`arm_abort_independence`)이 기존 보고 플래그 기준(v2 V5의 p ≤ .10)에 걸린다.
   - (iii) 그 호스트의 `cell-results`·시작 게이트 상태·로그가 기록 완전성 검사를 통과하지 못하거나 증거 해시 대조가 안 된다.
   - (iv) 정지가 oracle 값 열람 이후의 사람 판단으로 일어났다(봉인상 있어서는 안 되는 경우).
4. **보고 문구 규칙.** 리포트·표·보고서에 미완료 seed 수, 완주 seed 블록 수, 중단 원인, 실제 완료 범위(호스트별 seed 목록)를 적는다. "EXP-3 train 완료"가 아니라 "부분 완료(호스트 X 미재개 정지)"로 쓴다. "EXP-2 진행 가능(GO)"과 "holdout 전체 완료"를 다른 항목으로 보고한다. holdout은 마감 절단과 가동 호스트 수에 따라 상한 120 seed에 못 미칠 수 있다.
5. **동결.** 이 규칙은 train 결과 확인 전에 이 설계 PR의 머지로 승인되고, exp3-v1·exp2-v1 동결본에 들어간다(제안 P9-b, P9-c).

## 10. 실행 가능성 (추정, abort·정지 무시)

유일한 실측값은 HOST1 jobs 2 약 4,760 exec/h(실시간, EXP-0)다. HOST2는 미측정이다. 아래는 abort와 정지를 무시한 산술이며 보장이 아니다.

| 항목 | 실행 수 | HOST1 한 대 | 비고 |
| --- | --- | --- | --- |
| 적격성(호스트당) | 24,000 | 약 5.0 h | |
| EXP-3 train | 120,000(20 seed × 3 arm × 2000) | 약 25.2 h | 두 호스트면 HOST2 처리량에 달림(UNKNOWN) |
| GO 최소(76 seed) | 456,000 | 약 95.8 h | |
| holdout 상한(120 seed) | 720,000 | 약 151.3 h | |

실행 창은 train 시작을 동결 시각 2026-11-18 12:00 KST로 두면 마감 2026-11-25 12:00 KST까지 168 h다. 한 호스트, 판정 지연 0, e = 1을 가정하면:

- train 종료 약 11/19 13:12, H_rem 약 142.8 h, 용량 ⌊142.8 × 4,760 ÷ 6,000⌋ = 113 ≥ 76이다. **GO 최소(76 seed, 약 456,000 실행, 약 95.8 h)는 창 안에 들어간다**(train 25.2 h + 95.8 h ≈ 121 h < 168 h).
- **holdout 상한(120 seed, 약 720,000 실행, 약 151.3 h)은 한 호스트로는 창 안에 들어가지 않는다**(25.2 h + 151.3 h ≈ 176.5 h > 168 h). 이 가정에서 holdout은 마감에서 약 113 seed로 잘린다. n = 120은 상한이고, 마감에서 잘리면 완료된 블록으로 분석한다(D040 운영 조건). 오케스트레이터 결정 문장의 "상한도 창 안"은 이 산술과 맞지 않아 §16에 적었다.
- 두 호스트이고 HOST2가 HOST1과 같은 처리량이면 상한도 들어간다(train 12.6 h + holdout 75.6 h). HOST2 처리량은 미측정이다.
- 정지·abort·승인 대기가 있으면 값은 달라진다. 모두 abort·정지를 무시한 추정이다.

한 호스트만 참여하면 ①의 교차 대조와 ②는 해당 없음으로 적는다. 따라서 "Docker 실행 환경의 중대한 불일치 해소"의 기준은 ①, ②의 보류 조건, ③④, ⑤다.

**연구 타당성 조건(원문 그대로, 변경 없음).** 호스트 간 성능·효과 차이를 Engine 버전만의 영향으로 해석하지 않는다. Engine과 하드웨어는 호스트에 종속된 교란요인이다.

1. 같은 호스트·같은 seed 블록 안에서 세 arm의 배치 균형을 유지한다.
2. 분석에서 호스트별 효과를 구분해 확인한다.
3. 호스트별 결과가 크게 다르면 이질성을 보고하고 원인을 조사한다.
4. Engine과 하드웨어를 호스트 종속 교란요인으로 사전등록에 명시한다.
5. 사전등록한 분석·중단 기준은 결과를 확인한 뒤 바꾸지 않는다.

10. **실행기 차이 — 해소.** 적격성 실행은 본실험 런처 설정 그대로(MAX_ATTEMPTS 2) 돌린다. 본실험 경로를 그대로 시험하기 위해서다. 판정은 첫 시도 기준이다. 첫 시도가 무기록·abort·기록 어긋남이면 재시도가 성공했어도 abort 분자에 센다. 재시도 발생 수는 따로 보고한다. v2의 "재시도 0"과 다른 점은 이것뿐이며, 첫 시도 기준이므로 Q7은 재시도 없는 판정과 같은 셀을 abort로 센다(§5 Q7).
11. **단일 호스트 실행 가능성 문장 — 확인됨(W4).** 검증자가 재계산해 121.0 h / 176.5 h / 약 113 seed를 확인했다. 오케스트레이터 결정 문장은 "단일 호스트로도 GO 최소(약 456,000 실행)와 상한(720,000)이 추정상 실행 창 안에 들어간다"였다. 같은 가정(HOST1 약 4,760 exec/h, train 시작 11/18 12:00, abort·정지 무시)으로 계산하면 GO 최소는 들어가지만(train 25.2 h + 95.8 h ≈ 121 h < 168 h) **상한은 들어가지 않는다**(25.2 h + 151.3 h ≈ 176.5 h > 168 h, 마감에서 약 113 seed로 잘림). 그래서 이 파일과 D047은 "GO 최소가 창 안"으로만 적었다(§9·§10). 상한 미달은 D040의 "n = 120은 상한, 마감에서 잘리면 완료된 블록으로 분석"이 처리하며 규칙 변경은 필요 없다.

12. **비교 불가 셀의 설명 절차 — 결정됨(ORCH 2026-11-11, 지웅 승인 = PR 머지; 검증 N2로 수정).** 기록 없는 쪽 호스트에서 1회 재실행해 비교 가능하게 만든 뒤 일반 절차로 넘긴다. 미해소 셀은 수만 보고하고 중대한 불일치 계산에는 넣지 않는다. 재실행 뒤 비교 가능 셀이 10개 미만이면 "교차 비교 미완"으로 보고하며, 이는 자동 보류 사유가 아니라 동결 전 지웅 결정 항목이다(결정 입력은 비교 가능 셀 수와 미해소 사유뿐). abort는 Q7 등이 이미 세므로 다시 세지 않는다(§7).
